# 落格 · DropNest

常驻 Mac 桌面的文件收纳窗。把文件拖进来，落格读取归档总目录下已有的文件夹结构，用本机 Qwen3.5 9B 根据内容选择合适位置，没有合适目录时自动创建；通过本地索引搜索文件名、路径和正文。

## 使用

1. 打开 `build/DropNest.app`，点击设置按钮，选择一个包含你现有分类的归档总目录。
2. 等待目录与内容索引完成；原有文件只读取，不会自动搬动。
3. 拖入新文件：自定义名称规则优先，其余由 AI 优先选择现有目录。没有合适位置时按内容自动创建新文件夹；只有线索不足或 AI 不可用时进入「待整理」。
4. 点击桌面卡片顶部的放大镜，或在设置中选择「搜索文件」，输入文件名或内容关键词。
5. 搜索结果可直接打开，或在 Finder 中显示。整理记录仍可查看去向、原因并撤销。

收纳窗大小为 210 × 224 点。除按钮和文件投放区外，按住任意位置都可拖动窗口，并自动记住位置。它放在桌面层，普通应用窗口会盖住，不跟随到其他桌面或全屏应用。菜单栏可显示、隐藏或退出；设置中可开启登录启动。

## 学习目录并按内容归档

- 读取总目录下的真实文件夹、代表性文件名及少量已有正文，作为用户分类习惯的线索。
- 逐层选择目录，直到合适的具体子目录。目录较多时分批比较，不简单截掉后面的候选。
- 选择已有目录时，模型只返回候选编号，由程序映射为本机路径。没有合适目录时，单独请求新目录名称；每次最多新建两层，每层最多 40 字，校验后只能在归档范围内创建。
- 优先复用已有目录；父目录合适、子目录不合适时可在该父目录下新建。新目录立即参与同一批后续文件的归档，不等下次启动。
- 新目录按主题、客户或项目命名，不采用固定分类表；拒绝路径穿越、隐藏目录、应用包以及「其他」「未分类」等兜底名。大小写或 Unicode 等价的目录复用已有名称。
- 真正移动前再次检查所选目录是否存在、是否仍位于归档总目录内。目录已删除或发生危险变化时保留原文件并提示。
- AI 关闭、不可用或文件线索不足时进入「待整理」。找不到现有目录本身不会直接触发兜底。
- 自定义名称规则仍然优先，可由用户明确指定相对子目录；这类规则允许创建指定目录。
- 拖入的文件夹整体移动；仅依据文件夹名等可用线索判断，不拆散内部结构。
- 设置中的「重新整理待整理」仅处理该文件夹的直接子项，文件夹作为整体处理；已明确归档到其他目录的文件不会重排。仍无法判断的文件留在原位。每次重整都有独立记录，可以撤销回「待整理」，再撤销早前记录可回到最初位置。

例如已有 `客户/星河科技/项目文书` 和 `个人/日本行程`，可根据协议内容或旅行预订内容分别归入这些目录，无需将名称改成某套预设分类。如果现有目录只有「代码」，拖入摄影学习笔记时可自动新建「摄影学习」，以后同类文件继续归入该目录。

## 发票按用途批量整理

在设置中打开「发票整理」，或使用菜单栏「整理发票…」。选择或拖入本批发票的文件夹，程序逐份读取文件，参考来源文件夹及原子文件夹名称，按 `来源文件夹 / 用途 / 类型` 归档。例如「10月差旅」这一批可以整理为 `10月差旅/出差报销/住宿`、`10月差旅/出差报销/交通`。

- 「本批用途」可填写出差报销、客户招待、项目采购等，明确填写的用途优先；留空时仅依据目录和票据中明确的业务线索判断，不能确认时进入「用途待确认」。
- 默认用途类型为交通、住宿、餐饮、办公用品、加油、通讯、服务、设备、材料，可编辑为自己的类型，用顿号或逗号分隔。模型只能选择本批类型，不能确认时进入「分类待确认」。用途和每个类型为不含斜杠的单层名称，最多40字。
- 支持 PDF、常见图片、XML、文本和 Word 票据。没有文字层的扫描 PDF 会用本地 OCR 识别前3页，分类最多读取6,000字线索。OFD、压缩包等不支持的格式保留原处，非票据或无法识别的文件也保留原处。
- 扫描预览只读取文件；点击「开始按用途整理」才移动。保留原文件名及空的来源目录，每次实际移动都有记录并可撤销。源文件在预览或分类后被修改时停止处理该文件，提示重新扫描。
- 所选文件夹也可以位于归档总目录内，仅在本页明确选择的范围内逐份重整；不能选择归档总目录或包含它的上级目录。已在对应用途、类型位置的文件不再搬动。
- 仍使用 Rust 内容查重；同批首次归档的发票参与后续查重，重复副本保留原处。普通桌面收纳区的文件夹仍整体移动，发票的逐份分类使用「发票整理」入口。

发票分类需要启用 AI。默认使用本机 Qwen；切换到云端需允许文件内容、目录线索及发票用途发送给所选服务。来源线索只包含所选文件夹名称及原子目录，不发送来源绝对路径。分类只用于文件管理，不判断抵扣资格或报销合规性。

## 找回文件

搜索包含原有文件和落格新归档的文件。支持文件名、完整相对路径和提取的正文，多关键词按相关性排序；中文短语也会拆分匹配。搜索结果显示目录、正文片段、修改日期，以及正文是否完整索引。

- 文本、Markdown、CSV、常见代码文件：最多提取 60,000 字符。
- PDF 搜索索引：提取最多前 100 页、60,000 字符；扫描 PDF 的搜索索引暂不做页图 OCR，发票专用分类另有前3页 OCR。
- Word、RTF、ODT：用系统文字转换工具提取正文。
- XLSX、PPTX：提取工作表或幻灯片 XML 中的文字，最多处理 100 个相关 XML 条目。
- 常见图片：通过 Vision OCR 提取文字，处理前将最长边缩至 1,600 像素。
- 不支持正文提取的文件仍可按文件名和路径查找。

索引在启动、改变归档位置、归档或撤销后更新。应用运行时持续监听归档目录及子目录：在 Finder 中新增、修改、重命名、移动或删除文件后，自动更新目录和正文索引，并刷新当前搜索结果。连续变化会短暂合并；索引期间发生的新变化会在完成后补扫，未变化文件复用已有正文。切换或清除归档位置时停止旧目录监听；监听不可用时会提示，仍可点击「刷新索引」。应用关闭期间的变化会在下次启动时扫描。

搜索有索引范围限制：单次扫描最多 20,000 个条目、24 层目录，总正文预算约 1,200 万字符。隐藏目录、符号链接、应用包内部和 `node_modules` 不递归扫描；达到限额、无法读取或正文截断会在界面中提示。

## AI 与隐私

默认通过 `http://127.0.0.1:11434/v1/chat/completions` 使用本机 Ollama 的 `qwen3.5:9b`。请保持已安装模型的 Ollama 运行；落格不下载模型或重启服务。无需 API Key。本机 Qwen 使用固定 JSON Schema、关闭长推理，限制输出为 512 token，并约束归档理由长度。

用于目录判断的正文片段最多 1,600 字符，每轮最多 12 个目录候选及少量已有文件线索。完整搜索索引留在本机，不送给模型。也可在设置中选择 Apple 系统模型或兼容云端接口；只有 Apple 模型需要 macOS 26+ 及 Apple 智能可用。

云端接口需明确允许发送文件名、内容片段和目录线索。升级前仅允许文件内容的设置不会自动扩大到目录线索。API Key 存入 macOS 钥匙串，远程接口要求 HTTPS，请求不跟随重定向。实际 AI 判断仍可能不准确，请通过记录核对并按需撤销。

本机数据位置：

- `~/Library/Application Support/DropNest/history.json`：移动及撤销日志。
- `~/Library/Application Support/DropNest/library.json`：目录结构和文件元数据；可搜索正文按路径哈希分 64 片存于同目录 `library-content/`，索引更新时只重写有变化的分片。均为明文存于本机，旧版单文件索引会在下次索引更新时自动迁移。
- macOS UserDefaults：归档位置与选项。

## 文件保护

归档前会检查文件内容是否已存在：先按大小筛选，再由 Rust 流式计算 SHA-256，并对相同摘要的文件逐字节确认。即使名字不同，内容完全相同也会跳过移动，原文件保留原处；整理记录标记「重复，已跳过」，可在 Finder 中查看已有文件。同一批次前面刚归档的文件也参与后续查重。同名但内容不同的文件仍加编号保存。

设置中的「重复文件」可只读扫描已有归档目录，按组列出内容完全相同的文件，支持打开或在 Finder 中显示。点击「一键清理」后，每组按路径排序保留第一份（列表标记「保留」），其余移到系统废纸篓，可从废纸篓恢复；清理后自动重新扫描并刷新索引。每次移动前重新核对扫描时的文件身份、大小、修改时间、完整摘要及实际内容，文件被替换、变化、丢失或路径出现链接时跳过并显示原因，部分失败不影响其余文件。清理期间不能切换归档位置，拖入的新文件排队等待。

检查可见普通文件，跳过隐藏文件、符号链接、应用包和 `node_modules`，文件夹仍整体移动。最多检查 20,000 个条目；目录不可读、达到上限或文件在比对过程中变化时，检查会提示未完成，当前待归档文件保留原处。大文件以 64 KiB 分块读取，不整体载入内存。检查结果对应扫描时刻，文件变化后应重新检查。

同名文件增加 `(2)`、`(3)` 等后缀，不覆盖已有文件。移动前先写日志。异常中断后的不确定记录标记为「需要核对」，不自动猜测恢复。

撤销前检查原位置是否被占用，以及归档项的身份、大小和修改时间；不能安全恢复时保留现状。此检查不是内容哈希校验，也不递归检测文件夹内部改动。损坏的历史不会静默清空。撤销恢复文件原位置，新建的空目录会保留，以便后续继续归档。

## 构建与验证

需要 Xcode 26+ 或包含 Foundation Models 的更新 SDK。本次使用 Swift 6.4 / macOS 27 SDK；应用最低支持 macOS 14，产物为本机原生架构。

同时需要 Rust/Cargo（Rust 1.94.1 已验证）。`build.sh` 会先构建 `rust/filecheck` 静态库，再经 C 接口链接到 Swift 核心；生成的应用无需安装 Rust。Rust 依赖版本固定在 `Cargo.lock`。

```bash
./build.sh
```

生成 ad hoc 签名的 `build/DropNest.app`，适合本机试用；对外分发需正式签名和公证。

```bash
bash scripts/build-rust.sh
CLANG_MODULE_CACHE_PATH="$PWD/.build/module-cache" \
SWIFTPM_MODULECACHE_OVERRIDE="$PWD/.build/module-cache" \
swift test --disable-sandbox --cache-path "$PWD/.build/cache"
```

Rust 核心测试：`cargo test --locked --manifest-path rust/filecheck/Cargo.toml --target-dir "$PWD/.build/rust"`。

测试覆盖移动、重名、撤销、中断恢复、路径与链接边界、扫描自定义目录、按正文搜索、索引持久化和更新，以及模型返回编号、新目录校验、自动建目录、后续复用、内容搜索和撤销。文件监听测试使用真实临时目录，验证新增、正文修改、重命名、移入移出、删除、切换与清除归档目录、索引期间补扫和自身写入过滤；运行这些测试需要允许测试进程访问 macOS 文件事件服务，受限执行沙箱可能无法启动监听。

本次发票更新验证：76 项 Swift 离线测试通过，本机 Qwen 发票实连测试通过（虚构住宿及交通票据各1份）；Rust 核心现有1项测试通过，其余3项 Qwen 实连测试本次未开启。发票测试覆盖来源子目录、用途优先、类型编号边界、用途不明确、非票据保留、扫描 PDF OCR、归档内指定范围重整、修改保护、同批重复、位置已正确及撤销。查重测试覆盖改名副本、同名同大小但不同内容、跨读取块比对、空文件、同批归档、待整理自排除、不可读文件保护和重复记录持久化。清理测试覆盖每组保留一份、内容变化、同名替换、保留文件途中移走、父目录变成链接、废纸篓失败、系统废纸篓恢复及清理期间新文件排队；系统废纸篓测试只移动临时生成的文件并恢复。

```bash
DROPNEST_LIVE_QWEN=1 \
CLANG_MODULE_CACHE_PATH="$PWD/.build/module-cache" \
SWIFTPM_MODULECACHE_OVERRIDE="$PWD/.build/module-cache" \
swift test --disable-sandbox --cache-path "$PWD/.build/cache" --filter QwenLiveTests
```
